## Claude 的四项主要意见

1. **过期页面影响整批回执**：逐页确认并分别报告过期、摘要失配、跨会话等原因；有效页面不被其他页污染。持久草案依照草案 ID 与 manifest 重建，缓存淘汰或后端重启不改变正文。普通临时快照过期后仍明确要求重读。见 `2aa5ddd`、`4cbafee`。
2. **失效探针没有结果或唤醒**：未物化、排队失效、关闭探索及永久业务错误均可形成持久结果和通知；通知经既有确认和唤醒链交付，关闭后可处理已有结果。启动事务仍复检依据。真实宿主的失效和关闭场景分别记录在 `runs/pr11-host-stale.json` 和 `runs/pr11-host-off.json`。见 `90b8cac`。
3. **大材料要求同处一次请求**：固定材料按字节分页，同代同主会话可跨请求累计已确认范围；当前结项请求完整读取独立决策包。2,228,727 字节合成材料、中文/emoji 分页及先前页面离开上下文均有回归；完整 OpenCode 场景实际登记多页材料并以 qualified 结项。完整结构仍保存用于审计和 basis 比较。决策包上限为 32,000 字节，事实本身超限须显式缩小范围；[旧项目副本测量](project-evidence-sizing.json)显示这一限制对较宽的历史范围仍可能触发。见 `40f5cce`、`9265189`。
4. **确认可能被 2 秒期限挤掉且原因不可见**：证据确认与 memory 构建并行，共用原有 deadline；部分批次成功不被其他批次超时清除，失效/超时/后端不可用的原因进入模型可见说明。材料确认失败也会提示重读；结项缺页返回对应草案、已确认前缀和重读入口。保留原有有界时延，迟到回执不能追认已结束请求。见 `2aa5ddd`、`927c35c`、`a8858d9`。

## 保留的判断与 push back

- 材料 digest 证明字节身份，不能替代唯一核心材料的实际交付；限定回答中的非核心影响判断仍须理由和证据。历史材料回执也不证明模型仍保有原文、理解了内容或科学结论成立。
- 未发现 Grok S9 所推断的 prepare/reconcile 无限风险变化循环。首次 scope 建立及相关挑战回归均已覆盖；不为未复现的循环加入必然触发的拒绝路径。
- 同字节自引用可以验证；轻微改写或语义相似不等于可自动判定的科学独立性，不引入语义相似度门禁。
- 版本专用迁移器继续拒绝错误起始版本，包括未来版本；调用端应按正确迁移链执行，不将错误静默转换为成功。
- 不为当前宿主契约之外的非对象回执项扩建通用防御层。合法的快照过期属于真实生命周期，已单独处理。
- 不新增 CI 服务、对象 GC、外部模型质量试验，也不强推拆分已审提交；这些不影响本轮修复验证的具体结果。
