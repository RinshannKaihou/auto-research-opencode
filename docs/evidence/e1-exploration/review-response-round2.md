# PR #11 第二轮评审处理

本轮在 `9a7b110` 之后修复。[Claude](https://github.com/RinshannKaihou/auto-research-opencode/pull/11#issuecomment-6555314976) 的材料确认阻断问题优先处理；[Grok](https://github.com/RinshannKaihou/auto-research-opencode/pull/11#pullrequestreview-5727071762) 与 [GLM](https://github.com/RinshannKaihou/auto-research-opencode/pull/11#issuecomment-6555323695) 的意见一并核对。验证输出及适用范围见[工程验证](README.md)。

## 修复

1. **材料确认失败**：确认以页为单位处理，批次之间的拒绝索引先换算回完整请求的页序。有效页继续登记；失效页在后续请求中给出精确引用、字节范围和原因，旧结果不再反复参与确认。暂时的后端故障允许重试；恢复固定对象后，可重新读取并确认新页。无关工具不等待确认，读取证据、准备或结项最多等待 2 秒；超时不计入已读。真实 OpenCode + 本地模拟 provider 的隔离场景保留旧页，移除并恢复合成固定对象，验证有效页与失效页、后续查询及重读恢复。
2. **决策包重复**：明确提交的 `risk_ids` 分组在模型收到的决策包中保留，每个风险仍单独执行原有校验；完整逐项判断仍保存于草案和结项审计，附录逐项列出风险与处置。材料的 `object`／`subpath` 仅在身份中确有同值时去除重复副本。既有草案仍可读取和结项，结构快照、实际依据及风险不会被省略。
3. **验证与说明**：补充材料和草案的字节偏移说明、独立固定摘录需保留来源的建议、warm recovery 契约加载的回归。原宿主 JSON 是脚本汇总而非完整事件／RPC 日志；新增材料故障场景的合成工具结果记录，不声称涵盖全部宿主事件。

## 测量边界与保留意见

- 5 份历史项目独立副本的无判断占位包从 15,230／28,612／64,856／26,710／43,536 字节变为 15,230／26,062／59,960／23,548／39,531 字节。两份仍超 32,000 字节。这不是实际草案：真实范围、材料读取、审阅与风险判断都会改变结果；没有把 Claude 的四份推算当成真实结项测量。32,000 字节上限保留，真正超限需显式调整范围。
- Grok N2 的重复观察会增加 `requests` 行，确认是非阻塞的空间开销。本轮未把批次 operation ID 固定或缓存所有结果：同一旧页可能先被拒绝、修复后又可确认，直接重放旧结果会破坏重试和逐页验证。保留需要后续单独设计的存储优化。
- Grok N3：新增 warm recovery 场景，阻塞首次 status 时 shell 前置钩子等待；释放后可观测到执行记录。仅证明该恢复路径，不能排除其他时序；未知契约不一律当作 `evidence-v1`，避免给 Legacy 加回同步等待。
- GLM 对受信宿主契约之外的非对象页面输入建议不扩建通用防御层。实际生命周期内的失效、后端异常与部分批次已分别处理。
- 大材料逐页交付可能昂贵；分批跨请求累计允许完整交付，但这不是实际成本或真实模型质量的保证。
