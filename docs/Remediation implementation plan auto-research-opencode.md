## 1. 起点、目标与复用边界

目标是让协调者保存可恢复的备选，用有区分力的小试探降低未知，基于结果选择下一步，并对最终回答和停止理由负责。

已有上下文读模型、知识版本、窄写工具、审阅生命周期、checkpoint CAS、运行预算、启动认领、停止恢复和协调者限制均继续使用。新建的是探索领域对象与决策闭环，不重做原 R1/R2，也不放宽 main 的执行权限。

核验材料见 [匿名历史核验摘要](./evidence/exploration-20261101/public-summary.json)。这些材料证明结构和契约现状，不证明新策略的研究效果。

已知基线：

- 两个 lineage 兄弟节点可以并发认领；缺少自动生成、选择与比较策略。
- 固定材料可用时，depends_on 不会等待前驱全部工作结束。后续比较不得假设它是未来结果汇合屏障。
- 普通负结果已有知识/发布载体，但没有稳定连接到路线处置及重新尝试条件。
- 当前结项仍能接受空知识引用、报告自引和自述 reviewed；E2 修复该契约。
- 两轮实际研究保存上下文仍为 memory-v2；上下文能力已开发不等于实际运行已启用。

## 2. 工作包总览

| 增量 | 工作包 | 交付边界 |
|---|---|---|
| E1 最小探索循环 | E1.1–E1.6 | 单个选择范围、多候选、顺序小探针、结果驱动选择、证据读取、可恢复执行意图 |
| E2 证据决策与结项闭合 | E2.1–E2.5 | 当前支撑集合、类型化审阅覆盖、四维结项、原子检查、同源报告与附录 |

E1 的事务、幂等、基本预算和重启正确性是首个增量的要求。E3 扩展的是复杂资源与路线管理，不能成为延后这些基础约束的理由。

## 3. E1：最小探索循环与证据读取

### E1.1 决策范围、路线与选择记录

建立版本化 scope、route 和追加式 decision，并通过关联表连接既有 node、knowledge 与 publication。最小对象字段沿用主设计第 4 节：目标、约束、比较条件、固定基线、假设、下一探针、处置及恢复条件。

- 路线与节点是多对多关系；想法未被选中前不创建 execution task。
- 路线处置与任务状态、假设评价分别保存；不扩写 NODE_STATES 来代替科学判断。
- main 管理项目选路；node_core 返回证据和建议，不改全局选择或预算；specialist 保持原权限。
- 使用 expected revision、operation id、证据 source_sequence；旧选择不可覆盖新结果。
- 第一版支持一个当前选择范围。该对象不得覆盖或混同现有审阅 decision scope；审阅集合由选定材料和风险投影得到。
- 写入口只覆盖维护范围、路线、提交选择等必要操作，读取复用 query/workbench；不向模型暴露数据库表级操作。

主要落点：新增探索领域存储模块与 migration，复用 `native_store.py` 的事务/事件模式；接入 `service.py`、`query_store.py`、`workbench_read.py`、`plugin/src/tools.ts`。

验收：并发旧版本更新失败；同请求重放不重复追加；跨角色更新被拒绝；历史无路线对象不被补造数据；读查询不产生写事件。

### E1.2 重大选路所需的完整依据读取

从明确的决策材料与核心主张引用，获取 pinned/current 完整知识记录、scope、conditions、dependencies、evidence、checks、risk、review 与 provenance。支持同一读取边界下的分页、完整性标记和展开凭据。

- 复用 `knowledge_support_edges`，包含 grounded_in 和 knowledge-version evidence_refs 等支撑边；motivated_by 不变成失效传播边。
- 风险按当前依赖与影响判断，相关性未知时保留；不按年龄、候选标签或全局 in_use=false 隐去。
- 缺引用、遍历上限、无法检查和未支持类型进入 limitations；空集合不能证明没有风险。
- 完整读取只能证明材料已交付模型，不能证明模型理解或接受了内容。
- E1 提供可复用的检查预览和选路依据；最终提交的强制结项契约由 E2 完成。

主要落点：`context_policy.py`、`query_store.py`、`epistemic.py`、`review_lifecycle.py`、`frozen_refs.py`、`service.py`。

验收：被撤回依据即使无 impact row 也可发现；分页之后的相关风险不会遗漏；固定与当前版本并列；仅浏览不重算字段检查或改审阅状态。

### E1.3 探针执行与精简工作协议

区分材料侦察、可执行探针和工程深化，继续使用现有普通节点及其执行路径。任务类型是工作范围，不改变授权或预算口径。

- 探针只回答一个能改变选择的问题，可返回支持、反例、混合或信息不足。
- 明确预计成本和可调整的任务边界；5–10 分钟仅是特定任务估计，不是统一超时保证。
- 简单候选允许在同一个节点比较；独立判断、隔离改动或并发有价值时再拆节点。
- 只读 specialist 由 node_core 调用；性能测量、复算和重实现使用可执行节点。
- 最小交付为结果、条件、固定证据引用、仍未知事项及建议；不要求每个探针完成全套工程打包。
- 超时或预算耗尽走原有停止/退出核实，不自动标记假设 refuted。

主要落点：`memory_store.py` 的角色/任务指导、`plugin/src/tools.ts`、`plugin/src/engine.ts`、`plugin/src/specialists.ts`；复用 `runtime_budget.py`，不另建免预算执行器。

验收：读取专家不能调用命令；探针失败不产生科学反证；没有完整工程产物的负结果仍可正常发布和交回。

### E1.4 结果触发选择与执行意图

关键结果产生持久的待决策项；同批结果可合并，心跳和相同结果不重复触发。协调者明确选择深化、转向、组合建议、暂缓或提出停止，并引用其考虑的路线版本和结果。

- 一次选择可以支持一个新的小探针，也可暂不执行；程序不凭分数替模型决定科学优先级。
- 选择记录与待执行意图在同一事务持久化；实际宿主派发仍由既有认领与恢复路径完成。
- 重启先核实已有意图，重复通知只消耗一次；预算不足时保留意图状态，不伪造已执行。
- 不用“相关节点都关闭了”代替结果已被选择过程处理；缺失结果明确记录。
- 路线文字编辑和反复排名不自动重置 idle；需新增证据、实际工作或有依据的决策变化。

主要落点：探索领域层、`workflow_store.py`、`runtime_budget.py`、`plugin/src/engine.ts` 结果通知与续轮路径。

验收：结果到达后发生一次可追踪选择；一次负结果可触发其他路线；重启/重复投递/预算到限均不重复启动。

### E1.5 上下文与最小可见性

协调者看到当前目标、关键未知、当前路线、最强剩余替代、未处理结果和当前风险；所有候选可通过稳定引用及游标取全。摘要和索引不改变知识或路线状态。

新探索模式必须声明并核验所需 context 能力，复用现有新版读模型；不能启用探索流程却静默缺失路线块。旧模式保持可用，不批量切换既有项目。上下文策略、探索策略和结项契约版本分别记录。

主要落点：`context_policy.py`、`memory_store.py`、`plugin/src/research.ts`、`query_store.py`、board 的路线列表/详情入口。

验收：候选多、风险多和小上下文预算时，关键索引仍完整；暂缓路线可恢复访问；blind specialist 不收到全局路线排名；只读视图不产生迁移或关系。

### E1.6 首个端到端交付

完成“定义范围 → 保存候选 → 选择探针 → 发布结果 → 转向/深化 → 保存停止建议”的单范围闭环。采用普通节点和现有预算，不依赖 E3 才能运行。

同时保留当前最终结项漏洞的明确状态：E1 的停止建议和风险预览不等于 E2 已完成，不对外声称已经阻断空引用或自述 review 的全部问题。

## 4. E2：证据决策与结项闭合

### E2.1 当前支撑集合和风险合并

将 whole-publication/item final_ref 解析到 owner；从声明的核心 claim 集合与固定证据取支撑祖先，合并当前 publication_check、field checks、pending impacts、dispositions、挑战与 coverage 限制。

后端只检查已声明引用，不宣称发现了正文全部断言。缩小 declared set 或 scope 必须留理由、历史和相应报告范围；移出范围不等于风险被解决。

主要落点：`epistemic.py`、`frozen_refs.py`、`review_lifecycle.py`、`conclusion_store.py`，复用 E1.2 的读取能力。

### E2.2 审阅类型、独立性和覆盖

复用精确版本的 review obligations/reports，区分任务完成与科学问题处置。登记审阅对象、类型、结果、实际模型、上下文限制、独立性及挑战处置。

引用/范围/措辞审阅可使用只读 specialist；重算、重实现和对抗实验需要普通节点。调用现有能力不需要 main 获得 delegate 或 shell 权限。不同会话不自动等于独立，不完整覆盖保持 unknown/partial。

`reviewed` 必须由适当类型和精确版本的覆盖支撑；最终报告自引或任意 frozen refs 不能产生该标签。没有审阅仍可诚实结项为 unreviewed；不要求每个祖先执行同一种复核。

### E2.3 四维结项契约

保留 outcome，增加证据闭合和探索停止的结构化信息，并将 review coverage 单独表达。每项相关风险记录 core_impact、reason、evidence_refs、disposition 和 gap。

| 情形 | 允许的回答与证据状态 |
|---|---|
| 核心问题已回答，当前范围内已知证据问题得到处理 | 可 answered；可 resolved，review 仍单独计算 |
| 仅有明确不影响核心答案的边界/机制缺口 | 可 answered + qualified，逐项保留理由与 gap |
| 已知未解决风险削弱核心答案，或核心影响仍未知 | partial/unresolved；不得 answered |
| 无结构化核心依据或引用覆盖不明 | unknown；补齐依据或按 partial/unresolved 结项，不能空集 reviewed/resolved |
| 某支撑路径、检查或引用类型不完整 | 显示限制并判断核心影响，不能把遗漏当通过 |
| 仅有历史自述 review 或一份冻结报告 | 保留历史语义；新派生覆盖 unknown |

探索停止记录列出当前范围内已考虑路线、已到/缺失结果、未做原因、残余不确定性和恢复条件。允许目标已达成、下一步代价不合算、资源受限或用户停止；这些理由不能被解释为全局最优或穷尽所有可能。

执行来源未知、没有确认性注册或没有独立复核，本身不使探索性 answered 失格；只有其确实影响核心回答时才限制 outcome。非核心开放问题和无关历史 backlog 不阻断结项。

### E2.4 原子提交与停止优先

最终提交在单一事务重新计算当前风险、路线和决策版本，保存有事件上界的检查快照。旧 preview 之后的撤回、挑战、重要结果或范围变化使其失效时，返回差异并要求重新处理。

保留既有 live work/退出未核实约束。用户停止、预算暂停先控制执行；若剩余预算不足以综合，不自动伪造结论，也不为了补表单继续实验。保留部分产物、未结论状态和恢复入口。

启用新结项契约后，旧 API 路径不能绕过它；功能开关不能把同一研究代静默降回宽松结项。

### E2.5 最终报告、证据附录和展示

从 E1.2 同源读取生成 evidence appendix，报告、附录、核心引用和读取凭据的版本/哈希保持一致；条件变化需重新读取。看板分别展示回答程度、证据闭合、审阅覆盖、探索停止理由。

保留语义复核：有限零命中不等于不可能，平均成本份额不等于服务 p99 上限，微基准提升不等于真实服务改善。程序检查能揭示引用和条件，不保证标题没有过度概括。

主要落点：发布/读取路径、`conclusion_store.py`、`plugin/src/tools.ts`、board、两份 README 的契约说明。

## 5. E3：复杂多路线管理

| 工作包 | 内容 | 验收要点 |
|---|---|---|
| E3.1 多范围和关系 | 多路线跨节点；比较节点跨路线；可选子范围；明确竞争、依赖、互补 | 不强制单父树；同一证据不被复制成多份独立支持；改变目标产生新范围版本 |
| E3.2 分批预算与共享资源 | 小额投入后追加；全局预留；公共探针一次记账；活跃路线与候选清单分开 | 不超总额；候选数量不等于并发额度；未核实退出不释放不确定用量；设备测量可串行、其他分析仍并行 |
| E3.3 异步汇合与比较 | 预期/已到/缺失结果；临时选择；迟到证据修订；固定比较条件 | 不默认最先返回者胜出；未发布材料不作未来引用；不同数据、单位、基线或环境不能直接排名 |
| E3.4 组合与恢复 | A+B 新实验；交互与约束检查；从冻结基线恢复；带条件复用负结果 | 不相加百分比；组合失败保留单路线结果；无新理由不重复原死路，条件变化可恢复 |
| E3.5 长期状态与可视化 | 精确版本与执行意图恢复；跨目标适用性检查；路线历史、预算和缺失结果展示 | 多路线重启后不重复派发/覆盖新选择；摘要不会永久隐藏暂缓路线；图与列表均来自同一账本 |

主要落点：探索领域层、`runtime_budget.py`、`workflow_store.py`、`plugin/src/engine.ts`、固定输入与 workspace 准备、query/workbench/board。

科学状态不从进程状态自动推断。路线排除与实际任务取消分别处理；迟到结果仍保存，可能触发重新选择。源码目录隔离不等于设备隔离，也不等于强执行来源。

## 6. 贯穿工作与验收

### V1 工程契约与回归

复用已有上下文、R2、运行控制、权限、结项、只读浏览和独立打包测试。新增测试应覆盖会改变研究行为或持久状态的情形：

- 路线版本冲突、幂等请求、重复通知、派发前后重启、预算不足和迟到结果。
- 负结果、未知、执行失败和取消的区别；旧项目缺路线数据的兼容行为。
- 固定与当前依据差异，撤回/挑战发生在结项 preview 之后，范围缩小不能洗掉风险。
- 空核心依据、报告自引、审阅完成但挑战未处理、合法 answered + qualified。
- 多路线测量不可比、共享资源争用、组合退化和条件改变后的重新激活。
- 主协调执行边界、node_core 权限、盲评上下文、只读不迁移、内置 Python 与源码一致。

参考现有 `test_context_policy.py`、`test_r2_checkpoint.py`、`test_r2_review_fixes.py`、`test_runtime_control_repair.py`、`test_runtime_control_review.py`、`test_p0_contracts.py` 等。渲染形状可调整，风险传播和历史语义断言不能直接删除以换取通过。

### V2 模型研究效果

从 E1 起建立并运行匹配对照，不能以测试数量替代。任务至少覆盖：错误初始前提、有价值替代、单一路径、分布改变、噪声/不可比、组合退化、资源中断。

比较现有模式、新版读取、仅探索提示、仅证据决策检查、完整探索循环；具体批次保留匹配的模型、工具、环境、预算与上下文条件。独立评分核心答案、过度概括、关键前提验证、有效转向、无效深化成本与停止理由，不能让框架为自己的结论打分。

记录模型/variant、策略/契约版本、墙钟、token、工具/设备使用及观测完整性。未知使用不按零算；保存文本统计、同状态 shadow 和真实模型效果分别报告。不要拿当前数据库生成的新 context 与历史 body 宣称同状态 A/B。

不设固定分支率、反证率、修订率健康值。保留失败运行、重复试验与变异，不能只挑成功案例。效果未证实时保持 opt-in。
